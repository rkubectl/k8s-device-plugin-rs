# v0.2.0

This release hardens the classic device-plugin and DRA runtimes and makes
UTF-8 paths part of their public Rust APIs. All six public crates share the
version; the deployable example remains unpublished. Rust 1.98 is required.

## Upgrade notes

This is a source-breaking release from v0.1.0:

- `DevicePath`, `HostMount`, configured metadata directories and protocol socket
  APIs use `camino::Utf8Path`/`Utf8PathBuf`. String arguments remain convenient;
  convert standard OS paths explicitly with `Utf8PathBuf::try_from(path)`.
  `ValidationError::RelativePath` carries a UTF-8 path, and the obsolete
  `NonUtf8Path` variant is removed. See the [path migration guide](../../core/README.md).
- DRA plugin, resolver, registration, slice/status publisher and liveness-probe
  construction validates identity and returns `Result`. `ClaimResolver::new`
  requires the driver name; custom-path probes require the expected driver.
  A plugin's configured name must match `DraDriver::driver_name()`.
- Mock connection APIs use UTF-8 paths. Registration-server `socket_path()`
  returns `&Utf8Path`; use `.as_str()` for protocol strings or `.to_owned()` for
  independent ownership. Temporary fixtures use `camino-tempfile`.
- ResourceSlice names now include a bounded identity hash and explicit chunk
  index. Existing names migrate by creating the new generation before deleting
  stale slices with UID/resourceVersion preconditions.

## Correctness and capabilities

- Health-enabled DRA backends advertise the optional health protocol to kubelet.
  Reporting remains an explicit Cargo feature and backend opt-in.
- FirstAvailable preparation preserves allocation subrequest references
  internally and returns deduplicated top-level request names on the wire, so
  kubelet attaches CDI devices when a container selects a request.
- Claim resolution exposes only the current driver's allocations. Legal pool
  names containing slashes work, generated names are bounded, and reconciliation
  refuses cross-pool ownership collisions.
- The DRA service binds before registration is exposed. Liveness probes check
  the driver identity, advertised service and both real RPC endpoints.
- Classic Allocate tasks are cancelled with their RPC; container response order
  is preserved. Registration connections/RPCs have deadlines, unexpected clean
  server exits are errors, and zero polling intervals are bounded.
- The DRA inventory API supports explicit taints and binding conditions.
  Opt-in workload-claim, resource-pool status and read-only container-metadata
  adapters have integration guides under [docs](../getting-started.md).

Metadata publication retains its version-1 journal, immutable spec/document
bytes, descriptor-relative no-follow operations, retry behavior and mounted
inode preservation.

## Required DRA dependency override

Downstream applications must include this in their **root** Cargo manifest;
Cargo does not inherit a dependency's patches. Regenerate the application
lockfile after adding it:

```toml
[patch.crates-io]
h2 = { git = "https://github.com/rkubectl/h2", tag = "v0.4.20+20261023" }
```

This compatibility pin is required for real kubelet pluginwatcher registration.
See the [DRA integration contract](../../dra/README.md) for the removal gate and
complete setup instructions.

## Supported scope

The baseline targets Kubernetes v1.36 with stable `resource.k8s.io/v1` APIs;
optional v1.37 capabilities remain separate. Shared/consumable-device preparation
is explicitly rejected until supported end to end. `PoolDevice::health` is
informational; use inventory/taints for scheduling and the independent health
reporter for allocated devices. Runtime support is Unix, with Linux kubelet
deployments and macOS development/testing. Run futures retain process-lifetime
semantics.

This is a driver framework, not a turnkey hardware driver or production
deployment chart. Integrators supply the hardware backend, CDI artifacts,
appropriate RBAC and admission policy. Validation manifests retain `maxSurge: 0`.

## Validation

The implementation passed default/all-feature workspace tests, strict Clippy
and rustdoc, native ARM64 Rust 1.98 path regressions, and real kubelet/CDI tests.
Kubernetes v1.36.1 acceptance includes FirstAvailable without metadata and the
full metadata isolation/restart/writer-retry lifecycle. The third-review fixes
also passed v1.37.0 health negotiation and extended-resource consumption.
Detailed dated evidence is in the [DRA design](../dra-design.md).
