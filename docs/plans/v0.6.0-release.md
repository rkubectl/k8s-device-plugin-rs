# v0.6.0 release

Tracking: `k8s-device-plugin-rs-rwnh`. The maintainer authorized integration
and release after the completed core split and subdomain compatibility work.

## Scope and source

Integrate reviewed trial `a5d54056ff21b680f9806f85b6b16822798cbdc1` into
`main`. Release all eight public workspace crates at 0.6.0; keep the example
unpublished. The breaking minor release introduces independent classic and
DRA cores, validated identity types, always-compiled DRA health contracts with
explicit backend activation, and Kubernetes-compatible subdomain lengths.
Migration instructions are in `dra/README.md` and the core-split plan.

## Validation and execution

The implementation passed the final CI gate: 230 workspace tests, strict
Clippy and formatting, orchestration tests, and independent schema/feature
consumers. Native Kubernetes 1.36.1/1.37.0 DRA acceptance and later API boundary
checks are recorded in the core-split and subdomain plans.

Use an isolated clean `main` checkout, preserving original checkout edits and
private review files. Initialize the pinned kubelet submodule. Run the release
preflight and an explicit 0.6.0 preview; inspect versions, internal dependency
constraints and README replacements. Tag and push the source before invoking
publication with `release-publish.toml`. Independently retrieve all eight
published crates and record the exact tag/source and results afterward.

## Remaining assessments and limitations

Mixed-case driver-name compatibility remains separate task `rpj9` and does
not change in this release. Standalone kind CLI smoke was unavailable; the
native two-version DRA matrix passed. Existing pre-1.7 Container profiles were
preserved without exercising their restart compatibility. These are recorded
limits, not successful checks or additional functionality in this release.

## Publication evidence, 2026-11-08

- `mise run --jobs 1 release-preflight` passed from the clean isolated `main`
  checkout with `RUSTC_WRAPPER=` and the shared trial target directory. This
  reran CI (230 workspace tests, strict Clippy/formatting, 30 matrix, 5 profile
  and 14 multi-node mocks, plus independent schema/feature consumers). The
  task's default patch preview was followed by the explicit 0.6.0 preview.
- `cargo release 0.6.0 --workspace --exclude k8s-device-plugin-example
  --no-confirm` passed in dry-run mode. The version transaction updated all
  shared versions, internal constraints and four dependency snippets.
- The executed version transaction used `--no-publish --execute --no-confirm`.
  Release source `73e472dec13487442e4bd3a76c521e90a6a25222` was pushed to
  `main` with annotated tag `v0.6.0`, tag object
  `457a3e0e9fefa9c6dc9607db2d2eeebd44ebaa0c`. Local HEAD, remote main and
  the peeled remote tag matched before publication; the checkout was clean.
- `K8S_OPENAPI_ENABLED_VERSION=1.37 cargo release publish --workspace
  --exclude k8s-device-plugin-example --config release-publish.toml --execute
  --no-confirm` verified the packaged sources against a temporary registry,
  published all eight public crates in dependency order, and waited for their
  registry availability. The example was not published.
- A fresh Cargo cache independently retrieved every public crate with
  `cargo info NAME@0.6.0 --registry crates-io` outside the workspace. All eight
  downloaded `.cargo_vcs_info.json` files identify the exact release source
  above and do not report a dirty tree. This includes the new
  `k8s-device-plugin-dra-core` crate.
- The original checkout's tracked manifest edit and five untracked private
  review files were left untouched. Its working branch was not advanced;
  release integration and publication used the isolated clean `main` checkout.
