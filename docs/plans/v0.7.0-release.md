# v0.7.0 release

Tracking: `k8s-device-plugin-rs-6269`. The maintainer authorized preparation
and publication after the compatibility assessment. Reviewed implementation
source: `248b43d2829b04e4462c389406ffb266c2ad2153`.

## Scope and compatibility

Release all eight public crates at shared version 0.7.0; the example remains
unpublished. This release includes sixth-review hardening (`4xq0`), publisher
poll configuration (`8zix`, GitHub #3), and DRA resolver/publisher policies
(`97oi`). Migration and runtime defaults are documented in the core and DRA
READMEs and the corresponding implementation plans.

Use a breaking minor release, not 0.6.1:

- `ValidationError::NulByte` and
  `ExtendedResourceNameError::ReservedPrefix` extend public exhaustive enums;
  downstream exhaustive matches must handle the new cases.
- Classic resource-name validation follows Kubernetes, including quota-prefix
  rules and qualified suffix grammar. Previously accepted invalid names such
  as `requests.example.com/gpu` and `notkubernetes.io/gpu` are rejected. NUL
  paths are rejected before the wire boundary. Correct invalid configuration
  rather than relying on kubelet to reject it later.
- ResourceSlice chunk indices are padded to preserve numeric ordering. The
  publisher creates the complete new generation before conditionally deleting
  old names. Both native Kubernetes versions passed this migration. Consumers
  inspecting slice names should allow the new format.
- Existing polling, concurrency and retry defaults are unchanged; the new
  builders opt into customer-selected policies. Kubernetes 1.36/1.37 remain
  supported, with explicit health/metadata activation and the existing h2 pin.
  Classic core remains schema independent and now includes serde for checked
  extended-resource-name serialization/deserialization.

## Preparation and release procedure

Use an isolated clean `main` checkout and preserve original private review
files. Initialize the pinned kubelet submodule. Run the final release-preflight
CI gate, followed by the explicit 0.7.0 preview; inspect shared versions,
internal dependency constraints and four documentation replacements.

Execute with publication disabled, push and verify annotated tag `v0.7.0`
and its source commit, then publish from that exact clean source using
`release-publish.toml`, schema 1.37 and package verification. Independently
download all eight public crates into a fresh Cargo cache and verify their
Git source metadata. Record final evidence and close the release ticket in a
separate audit commit after publication.

## Prior validation and remaining scope

The sixth-review record includes native 1.36.1/1.37.0 slice migration, smoke,
health and extended-resource acceptance. Polling and policy builders passed
behavioral paused-time/API-mock tests, affected all-target tests, strict Clippy,
documentation and independent consumer checks under both schemas. Final
combined CI and packaged-source verification remain gates for this release.

Mixed-case DRA driver names, compatibility groups and additional timeout
configuration remain separate tracked work. No standalone kind CLI pass is
claimed; the earlier native acceptance limits remain in their original record.
