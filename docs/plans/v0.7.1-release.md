# v0.7.1 release

Tracking: `k8s-device-plugin-rs-xk04`. The maintainer authorized cutting and
publishing v0.7.1 after the compatibility discussion. Reviewed implementation
and documentation source: `271d3db` on main.

## Scope and compatibility

Release the eight public crates at the shared version 0.7.1. The example stays
unpublished. This compatible patch release adds explicit driver-scoped
ResourceClaim device-status removal, serves stable DRA health v1 alongside
v1alpha1, and clarifies field clearing and node-aware publisher RBAC.

Existing public types and method signatures remain compatible, with no new
public exhaustive-enum variants or dependency-version/MSRV changes. Kubernetes
1.36 and 1.37 remain supported; health activation remains explicit. Opted-in
kubelets select v1alpha1 on 1.36 and v1 on 1.37. The h2 compatibility snapshot
and consumer-selected Kubernetes schemas remain unchanged. Cargo `^0.7`
consumers may select this patch release.

## Gates and procedure

- [x] Use a clean temporary main checkout with the pinned kubelet submodule.
- [x] Run final `mise run --jobs 1 release-preflight` with `RUSTC_WRAPPER=`.
- [x] Inspect an explicit 0.7.1 preview: shared version, internal dependency
      constraints and four documentation replacements.
- [x] Execute the release with `--no-publish`; verify the pushed main and
      annotated v0.7.1 tag resolve to the same release source commit.
- [x] Publish from that clean source with `release-publish.toml` and schema 1.37.
- [x] Independently fetch all public crates in a fresh Cargo cache and verify
      their packaged Git source metadata against the release commit.
- [x] Close/synchronize Beads and commit the final publication audit separately.

Private `CODE_REVIEW-*.md` files in the original checkout must remain untracked
and untouched. Follow [the release guide](../releasing.md); do not change tagged
sources after publication starts.

## Existing implementation evidence

The [DRA acceptance record](dra-status-removal-health-v1.md) covers full CI
(251 workspace tests, strict Clippy, VM-free orchestration and consumer checks),
both supported schema suites, no-protoc generation and native v1.36.1/v1.37.0
lifecycle and health negotiation. The public status API probe passed removal,
absent-key no-op, data clearing and restoration on both API servers. Owned
profiles were deleted; original profile/builder/context state was preserved
with arm64 and `rosetta=false`. The subsequent RBAC documentation-only follow-up
passed formatting and strict rustdoc under both schemas (Beads `9hnd`).

This release requires the final assembled preflight and packaged-source checks
below; existing native acceptance is reused because no runtime behavior changed
after that run. No new cluster mutation or hardware qualification is included.
